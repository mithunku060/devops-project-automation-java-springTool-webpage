# DevOps CI/CD Project – Java Spring Boot Web App on Kubernetes (AWS EC2)

An end-to-end CI/CD pipeline that builds a Java Spring Boot web application, containerizes it with Docker, pushes the image to Docker Hub, and deploys it to a self-managed Kubernetes cluster running on AWS EC2 — fully automated through Jenkins.

**Application repo:** [devops-project-automation-java-springTool-webpage](https://github.com/mithunku060/devops-project-automation-java-springTool-webpage)

---

## Architecture Overview

```
GitHub (source) ─▶ Jenkins (build/CI) ─▶ Docker Hub (image registry) ─▶ Kubernetes (deploy)
                        │
                        ├── Maven build
                        ├── Docker image build & push
                        └── kubectl apply (deployment.yaml + service.yaml)
```

**Infrastructure:**
| Node | Instance Type | OS | Role |
|------|---------------|-----|------|
| Project2-master | c7i-flex.large | Ubuntu 24.04 | Jenkins, Maven, Docker, Kubernetes control plane |
| Project2-worker | c7i-flex.large | Ubuntu 24.04 | Kubernetes worker node |

---

## Tech Stack

- **Source Control:** GitHub
- **CI/CD:** Jenkins (Pipeline + Stage View plugin)
- **Build Tool:** Maven
- **Containerization:** Docker
- **Container Registry:** Docker Hub
- **Orchestration:** Kubernetes (kubeadm, v1.30.2, 2-node cluster)
- **Cloud:** AWS EC2

## AWS EC2 Setup

Two EC2 instances (`Project2-master`, `Project2-worker`) were provisioned with the following security group rules:

| Port | Purpose |
|------|---------|
| 22 | SSH |
| 80 | HTTP |
| 8080 | Jenkins UI |
| 6443 | Kubernetes API server |
| 30000–32767 | NodePort range (for exposing the deployed app) |

> For a production setup, scope these rules to specific source IPs / security groups rather than allowing all traffic — the "allow all" rule here was used for testing/learning purposes only.

## Setup Steps

### 1. Base OS update (both nodes)
```bash
sudo apt update
sudo apt upgrade
```

### 2. Install Jenkins (master node)
```bash
sudo apt update
sudo apt install fontconfig openjdk-21-jre
java -version

sudo wget -O /etc/apt/keyrings/jenkins-keyring.asc \
  https://pkg.jenkins.io/debian-stable/jenkins.io-2026.key

echo "deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc]" \
  https://pkg.jenkins.io/debian-stable binary/ | sudo tee \
  /etc/apt/sources.list.d/jenkins.list > /dev/null

sudo apt update
sudo apt install jenkins
```
Jenkins UI is then available at `http://<master-ip>:8080`.

### 3. Install Maven (master node)
Java is already available from the Jenkins install.
```bash
apt install default-jdk -y
apt install maven -y
```

### 4. Install Docker (master node)
```bash
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

sudo docker run hello-world
systemctl status docker
```

### 5. Install Kubernetes (both nodes)
Followed [Aareez01/kubernetes-v1.30.2-cluster-using-kubeadm](https://github.com/Aareez01/kubernetes-v1.30.2-cluster-using-kubeadm):
- Run steps 1–9 on **both** master and worker.
- Run the first command of step 10 on **both** nodes; run the second command (cluster init) on the **master only**.
- Copy the `kubeadm join` command generated by the master and run it on the **worker**.
- Run any remaining setup (e.g. CNI install) on the **master only**.
- Verify with:
  ```bash
  kubectl get nodes
  ```
  Both `Project2-master` and `Project2-worker` should show as `Ready`.

### 6. Configure Jenkins
- Access Jenkins at `http://<master-ip>:8080` and complete initial setup.
- Add **GitHub** and **Docker Hub** credentials under **Manage Jenkins → Credentials → Global domain**.
- Install the **Pipeline: Stage View** plugin.
- Add the pipeline job pointing to this repository, using the `Jenkinsfile` in the repo root.

### 7. Dockerize the application
- `dockerfile` in the repo root defines the application image build.
- Add the `jenkins` user to the `docker` group so Jenkins can run Docker commands, then reboot:
  ```bash
  sudo usermod -aG docker jenkins
  sudo reboot
  ```

### 8. Kubernetes manifests
- `deployment.yaml` — defines the app's Deployment (pod spec, replicas, container image).
- `service.yaml` — exposes the Deployment, typically as a **NodePort** service in the `30000–32767` range.

### 9. Run the pipeline
Trigger the Jenkins pipeline job. On a successful run it will:
1. Pull source from GitHub.
2. Build the app with Maven.
3. Build a Docker image and push it to Docker Hub.
4. Apply `deployment.yaml` and `service.yaml` to the Kubernetes cluster.

---

## Accessing the Application

Once deployed, the app is reachable via the worker node's public IP and the NodePort assigned in `service.yaml`:

```
http://<worker-node-public-ip>:<node-port>
```

## Notes / Possible Improvements

- Restrict security group rules (currently permissive for testing) to specific IP ranges.
- Add a container image scanner (e.g. Trivy) as a pipeline stage.
- Move Kubernetes manifests into a `k8s/` directory and manage via a Helm chart for reusability.
- Consider migrating from a self-managed kubeadm cluster to EKS for production use.
